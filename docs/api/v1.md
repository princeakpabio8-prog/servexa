# SERVEXA External API — v1

Developer reference for external integrations (e.g. VEYRA).

Base URL:

```
https://<project-ref>.supabase.co/functions/v1/servexa-api/api/v1
```

---

## Authentication

All endpoints require a server-to-server API key.

### How it works

1. An SERVEXA account holder creates an API key via the SERVEXA dashboard (stored in the `api_keys` table — only a SHA-256 hash of the raw token is stored).
2. The caller includes the raw token in every request:

```http
Authorization: Bearer sx_live_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
```

**Never send requests from a browser.** The raw token is a server-side secret. It is shown to the owner exactly once at creation time.

### Scopes

| Scope    | Grants access to             |
|----------|------------------------------|
| `read`   | GET endpoints                |
| `write`  | POST endpoints               |

### Error responses for auth failures

| HTTP | `code`              | Meaning                          |
|------|---------------------|----------------------------------|
| 401  | `missing_auth`      | No `Authorization` header        |
| 401  | `invalid_api_key`   | Token not found in database      |
| 401  | `api_key_revoked`   | Key has been revoked             |
| 401  | `api_key_expired`   | Key has passed its expiry date   |

---

## Request format

- All request bodies must be JSON (`Content-Type: application/json`).
- All UUIDs use standard hyphenated format: `xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`.
- Phone numbers must be in **E.164** format: `+2348012345678`.

---

## Response format

All responses return a JSON object.

### Success

```json
{
  "data": { ... }
}
```

List responses:

```json
{
  "data": [ ... ],
  "count": 5
}
```

### Error

```json
{
  "error": {
    "message": "Human-readable description",
    "code":    "snake_case_error_code",
    "status":  404
  }
}
```

## Endpoints

---

### `GET /api/v1/agents`

List all SERVEXA agents (campaigns) accessible with the provided key.

**Request**

```http
GET /api/v1/agents
Authorization: Bearer <api_key>
```

**Response 200**

```json
{
  "data": [
    {
      "id":          "uuid",
      "name":        "Loan Recovery Q3",
      "description": "Q3 loan recovery campaign",
      "objective":   "Recover outstanding balances",
      "status":      "active",
      "created_at":  "2026-09-03T10:00:00Z",
      "updated_at":  "2026-09-03T10:00:00Z"
    }
  ],
  "count": 1
}
```

**Agent status values:** `draft` | `active` | `paused` | `completed`

### `POST /api/v1/agents/:id/trials`

Start a trial call using the specified agent.

Internally delegates to the `start-customer-call` Edge Function (which triggers the CALL-E telephony provider). A trial record is created in `agent_trials` before the call is initiated.

**Request**

```http
POST /api/v1/agents/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx/trials
Authorization: Bearer <api_key>
Content-Type: application/json
```

```json
{
  "phone":          "+2348012345678",
  "customer_name":  "Amina Bello",
  "template_name":  "payment_reminder",
  "amount":         15000,
  "currency":       "NGN",
  "due_date":       "2026-09-15",
  "custom_context": "Customer was contacted last week, no payment yet."
}
```

**Required fields**

| Field   | Type   | Description                      |
|---------|--------|----------------------------------|
| `phone` | string | E.164 phone number of the callee |

**Optional fields**

| Field            | Type   | Description                                               |
|------------------|--------|-----------------------------------------------------------|
| `customer_name`  | string | Display name for the auto-created customer record         |
| `template_name`  | string | One of the standard call templates (see below)            |
| `task`           | string | Custom system-prompt override                             |
| `amount`         | number | Numeric amount (for financial templates)                  |
| `currency`       | string | ISO 4217 currency code, default `NGN`                     |
| `due_date`       | string | `YYYY-MM-DD` date relevant to the call                    |
| `custom_context` | string | Additional context injected into the agent's prompt       |
| `reference_info` | string | Free-text reference (account number, case ID, etc.)       |

**Standard template names:** `loan_recovery` | `payment_reminder` | `payment_confirmation` | `customer_followup` | `repayment_assistance` | `account_inquiry` | `custom`

**Response 201**

```json
{
  "data": {
    "trial_id":         "uuid",
    "call_id":          "uuid",
    "provider_call_id": "calle_xxxx",
    "status":           "initiated"
  }
}
```

**Response 502** — telephony provider call failed (trial record is still created, status `failed`).

```json
{
  "data": {
    "trial_id": "uuid",
    "status":   "failed",
    "error":    "CALL-E request failed"
  }
}
```

### `POST /api/v1/agents/:id/deploy`

Deploy an agent, creating a deployment record and activating the campaign.

> **⚠ Partially implemented.** A deployment record is created and the campaign status is set to `active`. Automated telephony provisioning (e.g. phone number assignment, inbound routing) is **not yet implemented** — `status` will remain `pending` until a provisioning worker is built.

**Request**

```http
POST /api/v1/agents/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx/deploy
Authorization: Bearer <api_key>
Content-Type: application/json
```

```json
{
  "environment": "production",
  "label":       "v1.2 deploy",
  "webhook_url": "https://your-platform.com/servexa-webhook",
  "max_calls":   500
}
```

All body fields are optional.

| Field         | Type   | Description                                            |
|---------------|--------|--------------------------------------------------------|
| `environment` | string | Free label: `production`, `staging`, etc.              |
| `label`       | string | Human description of this deployment                   |
| `webhook_url` | string | URL to receive deployment lifecycle events (future use)|
| `max_calls`   | number | Intended call cap (stored in config, not yet enforced) |

**Response 201**

```json
{
  "data": {
    "id":            "uuid",
    "agent_id":      "uuid",
    "status":        "pending",
    "config":        { "environment": "production", "label": "v1.2 deploy" },
    "error_message": null,
    "deployed_at":   null,
    "stopped_at":    null,
    "created_at":    "2026-09-03T10:00:00Z",
    "updated_at":    "2026-09-03T10:00:00Z",
    "_note": "Deployment record created. Full telephony provisioning is not yet automated..."
  }
}
```

### `GET /api/v1/trials/:id`

Retrieve the status of a trial started via `POST /api/v1/agents/:id/trials`.

Enriches the trial record with timing and status from the underlying SERVEXA call where available.

**Request**

```http
GET /api/v1/trials/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
Authorization: Bearer <api_key>
```

**Response 200**

```json
{
  "data": {
    "id":           "uuid",
    "agent_id":     "uuid",
    "status":       "initiated",
    "call_id":      "uuid",
    "started_at":   "2026-09-03T10:01:00Z",
    "completed_at": "2026-09-03T10:04:32Z",
    "call_status":  "completed",
    "failure_code": null,
    "created_at":   "2026-09-03T10:00:58Z",
    "updated_at":   "2026-09-03T10:04:33Z"
  }
}
```

**Trial status values:** `pending` | `initiated` | `completed` | `failed`

**Call status values** (reflected from the underlying call record): `queued` | `initiated` | `ringing` | `in_progress` | `completed` | `failed` | `cancelled`

| Field          | When populated                                              |
|----------------|-------------------------------------------------------------|
| `call_id`      | After the telephony call has been created                   |
| `started_at`   | When the call was answered / began                          |
| `completed_at` | When the call ended (maps to `ended_at` on the call record) |
| `call_status`  | Current SERVEXA call status (mirrors `calls.status`)        |
| `failure_code` | `connectivity_issue` if the call failed with that outcome   |

**Error 404** — trial not found or does not belong to the key's owner.

## Example: full trial flow (curl)

```bash
# 1. List agents to find an ID
curl -s \
  -H "Authorization: Bearer sx_live_your_token_here" \
  "https://<ref>.supabase.co/functions/v1/servexa-api/api/v1/agents"

# 2. Start a trial call
curl -s -X POST \
  -H "Authorization: Bearer sx_live_your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "phone": "+2348012345678",
    "customer_name": "Amina Bello",
    "template_name": "payment_reminder",
    "amount": 25000,
    "currency": "NGN",
    "due_date": "2026-09-20"
  }' \
  "https://<ref>.supabase.co/functions/v1/servexa-api/api/v1/agents/<agent_id>/trials"

# 3. Deploy an agent
curl -s -X POST \
  -H "Authorization: Bearer sx_live_your_token_here" \
  -H "Content-Type: application/json" \
  -d '{"environment": "production", "label": "VEYRA v1"}' \
  "https://<ref>.supabase.co/functions/v1/servexa-api/api/v1/agents/<agent_id>/deploy"

# 4. Check deployment status
curl -s \
  -H "Authorization: Bearer sx_live_your_token_here" \
  "https://<ref>.supabase.co/functions/v1/servexa-api/api/v1/deployments/<deployment_id>"
```

## Issuing an API key (manual, until UI is built)

Run the following SQL in the Supabase SQL editor as a project admin.
Replace `<owner_user_id>` with the UUID from `auth.users`.

```sql
-- 1. Generate a raw token (keep this — it is shown only once)
--    Prefix convention: sx_live_ for production, sx_test_ for test
with raw as (
  select 'sx_live_' || encode(gen_random_bytes(24), 'hex') as token
)
insert into public.api_keys (owner_id, name, key_hash, key_prefix, scopes)
select
  '<owner_user_id>',
  'VEYRA production',
  encode(digest(token, 'sha256'), 'hex'),
  left(token, 8),
  '{read,write}'
from raw
returning
  id,
  key_prefix,
  (select token from raw) as raw_token_show_once;
```

The `raw_token_show_once` column is returned only in this query. Store it securely — it cannot be recovered from the database.

## What is not yet implemented

| Feature                              | Status        | Note                                                    |
|--------------------------------------|---------------|---------------------------------------------------------|
| Automated telephony provisioning     | Not built     | `deploy` creates a record only; provisioning is manual  |
| Deployment webhook notifications     | Not built     | `webhook_url` in config is stored but not invoked       |
| `max_calls` enforcement              | Not built     | Stored in config, not checked at call time              |
| API key issuance UI                  | Not built     | Keys must be created manually via SQL (see above)       |
| Scope enforcement per endpoint       | Not built     | All authenticated keys have full access currently       |
| Trial call status polling            | ✅ Built      | `GET /api/v1/trials/:id` — see endpoint above           |
| Rate limiting                        | Not built     | Supabase edge rate limiting applies at infra level      |
